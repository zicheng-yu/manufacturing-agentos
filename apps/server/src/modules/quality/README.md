# 品质模块（YOU-123）

本模块负责客诉检索、8D 草案、整改逾期跟踪与客诉趋势，不读取其他领域的私有表。平台核心提供可选的评估前同步回调与事件解决入口，用于保证业务状态先同步，再计算和推送信号、态势。

## 演示场景

- 「偏光片鼓包」「触摸没反应」「画面明暗不一」检索相应历史案例；明确的围堵追问沿用同一症状，切换到包装破损等新问题时不带入旧案例。
- 「屏幕一闪一闪」规范为闪屏；演示案例库若没有对应案例，会明确说明没有足够匹配，不为提高命中率编造案例。历史编号可直接查询。
- 「为 CC-2610-05 起草8D」输出 D1–D8 草案和本客诉整改项；D4 是待验证假设，D5 为条件性历史参考，D6 是拟定验证计划。未指定或未收录的客诉不会自动换成另一条；已结案客诉只供复盘，不产生新的冻结任务。
- 同一对话追问「那D4呢」「D6如何验证」只聚焦指定步骤，保留同一客诉、症状和待核边界；「编号更正为CC-2610-09」会切换编号。明确否定的旧编号不再绑定，两个未作选择的客诉仍要求核实；切换到未登记的新问题后不会恢复旧客诉。
- 「CC-2610-05 的8D整改项有哪些逾期」只查看该客诉的整改项。历史根因、历史供应商与本次待核的责任归属明确区分。
- 「最近客诉趋势怎么样」展示近7天每日新增及前7天对比。按客诉编号计数，包含零值日期，排除未来和已取消记录；不编造品质成本、关闭耗时或没有基数的增长百分比。

## 检索边界

类别标签本身不能替代症状证据；检索不把历史根因文本中的词当作当前症状。常见否定描述会排除相应症状。规则匹配分不是置信概率。

只有具备较具体症状证据且类别相容的历史关联才自动产生疑似同类复发事件；黑屏等笼统现象或仅引用历史编号不会单独触发复发告警。本次根因仍需独立失效分析，事件保留客诉、案例和历史供应商来源。

客诉事件按 complaintId 作为持续状态合并，同一客诉重复上报不累加成多起投诉。历史数据若来自旧版 occurrence 口径，演示前应按项目原有流程重置演示数据；此变更不批量改写已有事件历史。趋势计数始终基于客诉业务表。

同一未结客诉补充或更正症状时，会更新业务记录并重新匹配历史案例，保留原受理日期、负责人和处理状态；匹配失效或变更时解决旧的自动复发告警，保留人工报告。已结案或取消的客诉不会因重复上报而重新打开。

## 自动整改跟踪

应用启动时从业务表检查逾期，种子数据不再预写逾期事件。应用现有每分钟信号/态势评估先通过 `beforeEvaluate` 同步业务告警，再统一计算和推送信号与态势；跨过截止日后无需有人提问也会产生 `capa_overdue` 事件。问答和整改更新也走同一评估入口。

跟踪复用现有服务检查，不新增定时器，也不订阅态势推送反向修改状态。重入保护让同步过程中产生的嵌套评估延后到当前批次完成，避免旧态势覆盖新态势；持续逾期保持同一状态事件，不累加次数。完成、取消或把期限改到尚未逾期时，相关告警通过现有事件机制解决并推送；重新打开且仍逾期时产生新的开放告警。尚无业务记录对应的外部告警不会被自动关闭。

日期按中国标准时间解释，截止日当天不算逾期，从次日开始。分钟检查依赖标准服务入口的现有评估循环；停止服务期间不会推送，重启后重新核对。

## 从草案到整改台账

生成8D草案或普通待办不会自动新建整改台账。确认事项、负责人、截止日期后，可调用受权限保护的 `POST /api/modules/quality/complaints/:id/capa`：

```json
{"title":"核实冷启动复现条件","owner":"品质负责人","due":"2026-11-03","confirmed":true}
```

必填字段必须有效，`confirmed` 必须明确为 true。客诉未收录返回404；已结案/取消的客诉不能新建，返回409。新记录返回201，相同客诉、标题、负责人、期限的重复提交复用原记录并返回200；已完成或取消的原记录不会因重试被重新打开。需要调整现有记录时使用更新接口，不通过重复创建修改期限或负责人。

新建记录立刻纳入逾期检查，未来到期的记录由服务的既有分钟检查继续跟踪。「那整改完成了吗」会沿用同一客诉并区分尚未建档、已完成和逾期。完成台账项不会自动关闭客诉，也不代表本次根因已确认或验证已通过。

## 整改项更新接口

`PATCH /api/modules/quality/capa/:id` 接受一个或多个字段：

```json
{"status":"已完成","due":"2026-11-03","owner":"品质负责人"}
```

状态限「进行中 / 已完成 / 已取消」，日期必须是真实的 YYYY-MM-DD，负责人不得为空。仅品质经理与董事长可访问，未登录返回401，其他角色403，未收录编号404，无效参数400。更新业务记录后立即同步告警；本次没有新增前端编辑页。

仓库根目录运行 `npm test`、`npm run typecheck`、`npm run build`。本目录测试覆盖口语检索与不误命中、话题切换、客诉身份与8D草案、无操作跨日告警、完成/延期/重开与权限、趋势窗口和模型上下文/失败降级；保留原董事长主线。
