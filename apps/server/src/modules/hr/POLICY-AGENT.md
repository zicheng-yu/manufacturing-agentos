# 公司制度助手

入口 `/employee-service`。所有已登录账号可查询员工可见的现行制度，并只查看自己的人工请求；HR 与董事长在 `/m/hr` 的「制度知识库」维护内容。

## 一次咨询如何完成

1. 员工描述问题。泛化的请假问题先确认假别，不创建工单。
2. 从已发布、已生效且未停用的版本中分段检索；配置模型时由模型理解自然语言并选择相关条款。
3. 服务端验证引用编号与逐字摘录。页面展示完整引用条款、制度编号、版本、适用范围和生效日期。模型不直接生成制度事实、金额、天数或业务操作。
4. 引用无效、模型失败时回到规则检索。个人工资、年假余额等个人记录与未覆盖问题转 HR，工单附最近六次提问，保留人工答复。
5. HR 把已解决问题整理为通用 FAQ 草稿，移除个人信息、确认适用范围后审核发布。下一次匹配咨询可以复用，统计中计入 FAQ 复用轮次。

目前使用 10 条历史演示制度。可以在页面粘贴真实制度文本，设置关键词、适用范围与生效日期；本次未接入真实企业制度，也不做 PDF、Word 附件解析。

## 知识维护

- `hr_knowledge_documents` 保存制度身份、类型、停用状态及可选来源请求；`hr_knowledge_versions` 保存不可变的已发布版本。
- 新建内容与修订先保存为草稿，草稿不会进入回答。发布要求明确确认内容可提供给公司内所有登录账号。适用范围描述条款的适用对象，不是访问权限过滤器。
- 已发布内容通过新版本修订；保存和发布校验草稿 revision，避免用旧页面覆盖或发布新修改。
- 支持未来生效日期。新版本到期前使用当前有效旧版本；新版本失效后不自动恢复旧版。
- 停用作用于整份制度。模型等待期间若引用版本被替换或停用，返回前重新查询现行版本。
- 审核后的通用 FAQ 是独立知识；来源问答删除时只解除来源关联，不删除已人工审核的通用知识。

## 权限与平台接入

`hr.service` 保留原 ID，更名「公司制度助手」，是唯一声明 `companyService` 的 Agent。这个标记只授予调用此助手的权限，不授予 HR 模块、招聘、组织数据、知识管理或其他员工工单的访问权限。

运行时允许异步 `context()` 和模块提供的 `preparedResponse`，以执行检索及引用核验后保存最终回答；通用模型撰写不会再次改写已核验答案。结果带 `policy.outcome`、`citations`、`questions`。其他 Agent 继续使用原流程。

## 接口

以下路径前缀均为 `/api/modules/hr`。

| 路径 | 权限与行为 |
|---|---|
| `GET /service/policies` | 已登录：当前员工可见制度与 FAQ，不返回草稿、历史版和审核管理字段 |
| `GET /service/requests` | 已登录：仅当前账号自己的请求与 HR 答复 |
| `GET /knowledge` | HR/董事长：全部知识版本 |
| `POST /knowledge` | HR/董事长：创建新制度、FAQ 或修订草稿 |
| `PATCH /knowledge/:id` | HR/董事长：提交完整草稿内容和预期 revision |
| `POST /knowledge/:id/publish` | HR/董事长：revision 与 reviewedForEmployees=true，审核发布 |
| `POST /knowledge/documents/:id/archive` | HR/董事长：停用或恢复整份制度 |
| `GET /service-metrics` | HR/董事长：问答、答复、追问、转人工、FAQ 复用轮次及实际平均响应耗时 |

问答继续使用 `POST /api/agents/hr.service/turns`，问题与历史保存在现有 conversations/turns 中。员工页面提供历史对话和「刷新进度」，不向其他部门广播 HR 事件。

## 验证与边界

- 自动化测试覆盖现行版本选择、未来生效、失效不回退、草稿隔离、并发修订、引用伪造、模型错误、停用期间的请求、跨账号隔离、FAQ 审核复用和统计。原 HR 与董事长主线仍通过。
- 真实 MiniMax-M3.1-Flash 样例：年假问题命中 P-01；「晚上干到第二天那笔补助怎么发」命中 P-05；请假先追问；个人余额转人工；未收录班车问题转人工。五个样例均符合预期，其中三次模型调用为 0.9–3.2 秒。
- 浏览器验证了补充病假信息后引用 P-02，以及「班车工单答复 → FAQ 草稿 → HR 审核发布 → 员工再次提问直接引用 FAQ」；浏览器控制台无 warning/error。
- 当前为文本分段、关键词召回与模型选择条款，单轮最多提供 24 个候选片段。规则模式的同义问法覆盖有限；大规模制度库需要补充检索评测及召回策略。
- 来源核验保证展示文字来自有效版本；条款是否充分回答问题仍需通过更多真实问法评测。现有使用统计按轮次计算，不能作为真实问答正确率、节省工时或人工替代率。
