# HR 模块

对应 Linear YOU-124。员工入口 `/employee-service` 提供公司制度问答与自己的人工请求；HR 在 `/m/hr` 管理员工服务、制度知识库、招聘初筛与岗位培训。制度版本、引用核验和 FAQ 审核复用见 [公司制度助手](POLICY-AGENT.md)。

## 员工服务

- 检索现有 10 条演示制度，扩充口语别名，回答展示制度编号与原文。
- 明确的省略追问可以沿用紧邻的制度话题；切换到班车、收入证明等未覆盖话题时转人工。个人余额、提取流程等制度未给出的细节列入待核。多意图问题保留已覆盖的制度依据。
- 转人工产生 `service_requested` 状态事件，通过 `onEvent` 写入 `hr_requests`，`hr_request_links` 记录事件、答复与处理人。同一账号同一归一化问题在事件未解决时复用请求；不同账号分别记录。
- HR 页面支持确认受理、填写答复、解决和重新处理。事件中心的状态操作同步请求和原始问答产生的待办；事件中心直接解决仅代表人工标记状态，答复需在 HR 页面填写。
- 删除产生请求的问答会删除对应事件、请求和关联信息。重复追问引用的仍是第一轮产生的事件，遵循平台已有的事件归属规则。
- 最近 7 天累计 5 条未解决的转人工事件产生积压信号；解决后不足 5 条会清除。旧演示请求 `REQ-301/302` 没有关联事件，保留原数据，可直接在 HR 页面处理，不参与此事件阈值。

数据库扩展增加请求关联表、HR 触发器和制度版本表；已有数据库启动时自动应用，无需重置演示数据。

## 招聘与培训

`talent.ts` 维护 4 个演示岗位的职责、技能要求和 12 门课程，岗位身份及状态来自 `hr_positions`。这些要求是演示岗位配置，不是模型补写的信息。

招聘表单一次核对一位候选人，填写匿名编号、相关工作年限与已评估技能。算法按技能 80 分、相关经验 20 分逐项计算；每项上限为其权重。技能等级为 0–3，缺失或别名记录冲突时不给总分。表格保留每项证据与面试核对建议，不修改招聘阶段。接口支持一次提交最多 20 位候选人，保留输入顺序，不接收年龄、性别等额外字段。

JD 草案引用岗位职责与要求，未收录薪酬、地点、班次和用工形式列为待核。

培训表单对照目标等级计算技能差距；已满足要求的技能无需补课，未评估技能生成评估行动项。确认的差距映射到课程、学时、建议日期和验收标准，工作台生成的行动项写入平台待办。课程按每周一门建议排期，讲师、人员与班次由用人部门确认。当前计划面向岗位，不做实名员工培训履历管理。

组织助手支持按问题中明确提及的部门过滤计划人数、岗位和离职预警，分析不包含员工姓名与离职原因。

## 接口

下表中的管理接口要求 HR 或董事长账号；员工自助接口的权限见公司制度助手文档。数据校验失败返回 400，岗位或请求不存在返回 404。

| 方法与路径（前缀 `/api/modules/hr`） | 用途 |
|---|---|
| `GET /requests` | 请求、状态、答复、处理人与关联事件 |
| `PATCH /requests/:id` | `{ status: "待处理" / "处理中" / "已解决", answer?: string }`；解决需有答复 |
| `GET /roles` | 岗位要求与技能 |
| `GET /roles/:id/jd` | JD 确定性分析 |
| `POST /screening` | 批量简历核对，返回分析，不写入问答与待办 |
| `POST /training-plan` | 培训预览，返回分析，不写入问答与待办 |

招聘输入示例：

```json
{
  "positionId": "POS-01",
  "candidates": [{
    "id": "C-01",
    "experienceYears": 3,
    "skills": [
      { "name": "供应商管理", "level": 2 },
      { "name": "成本分析", "level": 1 },
      { "name": "ERP", "level": 2 }
    ]
  }]
}
```

培训输入为 `{ "positionId": "POS-02", "skills": [...] }`，同样使用 0–3 的等级。HR 页面将表单转为结构化问答，调用已有 `hr.recruitment` / `hr.training` 智能体接口，保存分析、事实、待核项和培训待办。

## 验证

运行 `npm test`、`npm run typecheck`、`npm run build`。

- `policy-evaluation.ts` 包含 30 条问答样例：24 条常见问法（含需 HR 核定的婚育天数），加 6 条话题切换、未覆盖细节与混合问题。测试核对制度引用和转人工判断，不把这组样例通过率当作真实员工问答准确率。
- `hr.test.ts` 验证权限、请求落库与去重、答复和事件/待办状态同步、删除清理、迁移兼容、积压信号、评分边界、培训计划和新智能体问答流程。
- 浏览器离线验证：班车问题进入队列并保存人工答复；采购岗示例得到 85/100 的逐项核对；仿真岗两项差距生成 16 学时、两条培训待办。
- 招聘与培训的表格、评分、课程与事件来自规则分析。公司制度助手另有真实模型检索与引用核验测试，详见上述文档。
