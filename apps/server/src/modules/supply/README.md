# 供应链模块（YOU-122）

本目录实现物料与供应商查询、寻源比价、库存补货和供应商风险评分；不读取其他模块的私有数据表。

## 可演示的问题

- 「柔性板快断货了，几家供应商怎么选？」→ FPC-1203 的三家归一比价。
- 在同一对话追问「东莞德源要预付 30%，换无锡信创行不行？」→ 保留物料，列出指定供应商的含税价、MOQ 和交期缺口。
- 「FPC-9999 有没有报价」「FPC 找新星电子报价」→ 明确未收录/未匹配并生成核实与询价待办，不沿用先前物料。
- 「FPC-1203 找芯平有报价吗？」→ 供应商已收录，但该物料无报价，生成定向询价待办。
- 「精联风险怎么样？」→ 供应商资料、计分明细及风险表，不猜测物料。
- 「供应商有哪些？」→ 已收录供应商概览；在寻源对话中切换问供应商风险，也不会被旧物料绑住。
- 库存助手问「光学胶库存」「FPC-1203 和 DIC-0870 的库存」→ 仅显示选定物料，待办和缺料事件也只针对查询范围。
- 「10.25 英寸 FPC 库存」→ FPC-1025；尺寸未收录或尺寸与料号矛盾时要求核实，不用其他规格顶替。
- 库存助手追问「那还需要补多少？」→ 延续物料；「所有物料库存」→ 返回全库；「精联供的物料库存」→ 只显示现供关系中的物料，有报价但尚非现供的供应商会明确提示。

## 一笔明确采购需求的演示

寻源助手支持「需要2000片FPC，三天内必须到，哪家合适？」这类明确需求。数量按用户指定值比较，不改成系统默认补货量；到货期限按中国标准时间解释，以自然日估算报价的预计到货日期。

| 输入或追问 | 预期结果（现有演示报价） |
|---|---|
| 2000片FPC，三天内到 | 三家报价均晚于期限；明确暂无按期方案，最快报价仍需加急核实，不把排名第一包装成可按期采购 |
| 同一对话追问「交期放宽到十天」 | 保留2000片需求；按满足期限后的实际含税总额排序，现供昆山精联采购2000片、3.72万元，优先于单价较低但MOQ更高的方案 |
| 2000片FPC，五天内到 | 只有东莞德源报价交期可覆盖；采购量受MOQ影响为3000片，多采1000片，须核实超量、预付款和来料验证 |
| 问「换无锡信创行不行」 | 用同一需求核对指定供应商，展示其总额、MOQ超量及晚到天数 |

回复包含本次需求摘要、库存与在途核对、比价表、建议和待办。库存与在途尚未核实可分配量，不能直接当作本次需求的可用承诺；需确认指定数量属于新增采购量还是生产总用量，避免重复采购。所有采购决定仍由人核实并审批，系统仅生成待办。

数量支持阿拉伯数字、规范千位分隔和常见中文整数（如两千），以及「片/颗/套/件/个/箱/张」等单位；单位与物料计量单位冲突、数量范围、增减量或不规范数字会要求核实。仅给期限而未给数量时先询问数量，不偷偷使用默认需求。日期支持明确年月日、年内月日、几天内、交期几天及明确的今天/明天/后天到货；工作日、周几、过去日期或冲突日期需要确认。

同一物料的追问可保留数量和绝对日期；切换物料会重置需求。由于对话历史没有期限起算快照，上一轮的相对期限在追问时要求确认具体到货日期，不自动重新起算。付款账期与MOQ数值不当作采购需求。报价交期按本轮日期起算的自然日估算，真实现货、排产与运输仍需供应商确认。

## 补货与加急

净补货量计算保留已有口径：目标为安全库存加一周用量，扣除库存与全部未到货订单。库存正常时不推荐追加采购，补货建议单显示 0。

库存低于安全线且净补货量大于 0 时，创建补货和交期核实待办；如果在途总量已经足够，但到货前会缺料，则创建「加急现有在途订单并核实排产」待办，不生成「补货 0」。寻源助手在相同场景也优先建议加急，替代货源的数量只作应急比价参考；启用前需核对原采购单，避免重复追加采购。

未知料号、物料或供应商不会退回为全库库存回答，也不会因此生成其他物料的缺料事件。无关联现供物料的供应商只生成供货关系核实与询价待办。

## 风险分的口径

这是演示用的可解释规则分，不是违约概率，也不代表品质责任认定。

| 因子 | 分值 |
|---|---|
| 准交率 | `(1 - onTimeRate) * 100`，0–40 分 |
| 近 30 天延迟 | 每个不同订单 10 分，上限 30 分 |
| 近 30 天关联品质案例 | 每个不同客诉 15 分，上限 30 分 |

总分 0–100；30 分起关注，60 分起高风险。历史范围以事件首次产生时间为准，排除未来记录，已解决的事件仍属于这段历史。同一订单重复上报只计一次；客诉与它派生的复发事件按 complaintId 合并。没有供应商关联的客诉不会仅凭物料代码被归责到现供应商。品质因子仅使用事件账本里明确的 supplierId / supplier 关联，不代表全量历史案例库。

归属存在冲突时，延迟事件以现有订单台账中的供应商为准；品质事件优先使用明确的供应商 ID，再使用唯一匹配的名称。未知供应商 ID 不会通过名称被猜成已收录供应商。同一客诉在窗口内有多次报告时，以最新报告的归属为准；复发事件继承当前客诉的明确归属，历史案例的供应商名称不能覆盖它。冲突事件在风险表单列「归属待核」，并保留证据 ID，便于核实；这些关联不等于责任认定。

规则分、计分口径和归属待核信息会同时进入模型的文本上下文与界面表格。模型调用失败仍使用同一份规则分析、查询范围和待办；测试包含可控模型替身与失败降级，未替代真实模型服务的联调验收。

模块概览与寻源问答展示即时计算的风险表。有效订单的首次延迟上报会评估该供应商；寻源问答也会评估相关供应商，达到阈值时产生 `supplier_risk` 状态事件与供应商分组信号，进入驾驶舱和决策简报。单独的新品质事件会在下一次供应链问答或到货延迟评估时纳入告警，不增加跨模块事件钩子。风险事件按供应商去重，使用独立的计算事件 key，保留外部人工风险报告；风险处置完成后仍需通过现有事件流程解决告警。

物料追问采用保守的规则识别；无法识别的新主题会要求补充料号。供应商简称从已收录名称推导，不对未收录供应商编造报价或资质。
