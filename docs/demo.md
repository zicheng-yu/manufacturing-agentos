# 演示手册：在自己电脑上跑起来并完成演示

这份手册给要在自己电脑上演示的队友，也供评审者从代码仓库在本机运行。按当前项目安排提交公开代码仓库；[YOU-136「部署线上演示环境」已取消](https://linear.app/youonlyattendonce/issue/YOU-136)，演示不需要等待线上地址、云主机或 Docker 部署。先完成依赖安装，之后可在不配置模型密钥的情况下本地演示。

按顺序做完「一、准备」，演示当天按「二、开场前」和「三、演示流程」走即可。主线使用董事长账号；最后的可选权限演示会切换 HR 账号。

## 一、准备（演示前一天做完）

### 1. 装好 Node.js 和 Git

- Node.js **22.13 或更高**：终端运行 `node -v` 确认。没有就到 nodejs.org 下载 LTS 版安装。
- Git：终端运行 `git --version` 确认。

### 2. 拿代码、装依赖

```bash
git clone https://github.com/zicheng-yu/manufacturing-agentos.git
cd manufacturing-agentos
npm install
```

`npm install` 很慢或失败时，先换国内镜像再装：

```bash
npm config set registry https://registry.npmmirror.com
```

### 3. 配置 `.env`

在项目根目录复制一份配置（已有 `.env` 时不要覆盖）：

- macOS / Linux：`cp -n .env.example .env`
- Windows PowerShell：`if (!(Test-Path .env)) { Copy-Item .env.example .env }`

用编辑器打开 `.env`，核对以下配置。第一次运行可以保留示例值，并让模型密钥留空：

| 配置 | 填什么 |
|---|---|
| `LLM_API_KEY` | **可选**。留空就是离线规则模式，可查看数据、生成规则分析、回放事件及演示协作事项。要演示模型撰写时再填有效密钥；只保存在本机 `.env`，不要提交到仓库 |
| `DEMO_PASSWORD` | 本地演示默认 `agentos-demo`，也可自行修改；全部演示账号使用此密码 |
| `BRIDGE_TOKEN` | 本地回放必须非空；示例值为 `dev-bridge-token`。服务与回放脚本读取同一份 `.env` |
| `API_PORT` | 本手册使用默认后端端口 `8787` |

其余保持默认：数据集为赛道官方素材包；配置模型密钥后，模型为 MiniMax-M3.1-Flash。`AGENTOS_URL` 通常无需设置，回放默认连接 `http://localhost:8787`；如旧 `.env` 或终端环境中还设置了远程地址，先清除或改为当前本地后端地址。

### 4. 第一次跑通

```bash
npm run seed
npm run dev
```

浏览器打开 http://localhost:5173 ，账号 `chairman`，密码是你在 `.env` 里设的 `DEMO_PASSWORD`。

检查三件事：

1. 驾驶舱顶部横幅、六张态势卡都正常显示，右上角显示「实时连接」。未配置密钥时显示 `MODEL · 离线规则模式`，这是正常状态；配置密钥后显示模型名。
2. 进「智能体工作台 → 寻源比价助手」，点示例问题「线束快断货了，几家供应商怎么选？」，确认比价表、评分卡和行动项出现；模型模式下还会流式撰写正文。
3. 回答标注「规则分析」时，可能是主动使用离线模式，也可能是模型调用失败后的降级；仅仅能回答或页头有模型名不代表模型调用成功。需要确认模型连接时，看回答是否标注「模型撰写」。

确认无误后在终端按 `Ctrl+C` 停掉服务。

### 5. 可选：构建后用单个本地服务演示

如果只演示、不需要前端热更新，先停掉开发服务，再在项目根目录运行：

```bash
npm run build
npm start
```

打开 http://localhost:8787 ，前端由后端直接提供；这是本机运行方式，不是重新启动线上部署任务。第一次启动会自动写入演示数据。以后修改前端或图片后，需重新执行 `npm run build`。

| 本地运行方式 | 启动命令 | 浏览器地址 | 回放连接的后端 |
|---|---|---|---|
| 开发模式 | `npm run dev` | http://localhost:5173 | http://localhost:8787 |
| 构建后演示 | `npm run build` 后 `npm start` | http://localhost:8787 | http://localhost:8787 |

两种方式都保留运行服务的终端，再另开终端执行 `npm run replay`。下文以开发模式为例；选构建方式时，把启动命令换成 `npm start`，浏览器使用 8787 端口。

## 二、开场前（演示开始前 10 分钟）

1. 关掉其他可能占用 5173、8787 端口的程序（包括之前没关的本项目终端）。
2. 需要清空旧演示记录时，重置数据并启动（**先停服务再 seed**）。`seed` 会清空当前配置的数据库并重建演示数据，包括已有问答、待办和协作事项；需要保留记录时直接启动即可：

   ```bash
   npm run seed
   npm run dev
   ```

3. 浏览器全屏，页面缩放 100%，用 `chairman` 登录，停在「经营驾驶舱」。
4. **另开一个终端窗口**，进入项目目录，输入好 `npm run replay` 但先不要回车。
5. 不要提前回放，也不要在生成简报前先去问各个智能体：回放产生的 AGV 信号只在 2 小时内有效，智能体的问答也会写入待办和事件。

## 三、演示流程（约 4 分钟）

| 步骤 | 操作 | 讲什么 |
|---|---|---|
| 1 | 停在驾驶舱 | 这是董事长视角。六张态势卡来自赛道官方素材包：线束03 约 3 天后断料、多张工单预计延期、8 单致命不良未开 8D、AGV 按时率 83.7%、30 起高风险违规未闭环。每张卡都能点进去看原始数据。 |
| 2 | 在第二个终端按回车运行 `npm run replay` | 现场事件实时上报：注塑机 EQ-IM-012 振动进入故障前兆区 → AGV-02 送线束03 连续超时 → 苏州精工科技交付能力下降 → 振动超限 → 供应链部离职预警。看态势卡依次变化（约 25 秒）。 |
| 3 | 在「活跃信号」里点「EQ-IM-012 振动超限」 | 信号可以回溯到原始事件。回看素材包 16 次故障，每次之前都出现过「24 小时内 3 次读数进入 2.8 mm/s 关注区」，从那一刻算平均约 26.4 小时后出故障；这台设备历史上约 18 小时后发生过定位精度超差。注意这是故障样本回看，不是预测准确率。 |
| 4 | 点横幅里的「生成今日决策简报」 | 三件需要董事长决定的事，每件有负责人、时限和依据信号。「跨部门关联」把供应链缺料、AGV 配送超时和生产 OEE 的「缺料待料」损失串在一起。 |
| 5 | 进「智能体工作台 → 经营决策助手」，问「只能先做一件事，做哪件？」 | 按排序依据（严重度、是否需董事长拍板、时间窗）给出先做哪件，其余由谁跟进。 |
| 6 | 「寻源比价助手」问「线束快断货了，几家供应商怎么选？」，再追问「这笔采购要走什么审批？」 | 按《供应链管理制度》5.2 给五家供应商打分，4.1 给出审批路径；断料只剩几天时，按 4.2 走紧急采购（供应链经理先批后补）。 |
| 7（可选） | 左侧「公司制度助手」问「年假有几天？」，按提示回答「我入职 3 年了」 | 制度问答只引用官方制度原文（6.4 假期管理），并核对数字。 |
| 8 | 回驾驶舱，点开信号「线束03 缺料风险」，在抽屉里点「发起协作」 | 同一件事进入一个持久事项：目标、负责人、物料 M-10003、原始证据都在这里。再点一次只会打开原事项。 |
| 9 | 事项页「其他部门可能相关的信号」里，加入「AGV-02 配送连续超时」 | 依据写明是「共同物料 M-10003、共同原因标签 缺料待料」，是线索不是结论，要人点了才成为证据。 |
| 10 | 「岗位行动」选「寻源比价助手」提问，再选「AGV 调度助手」提问 | 两位助手的事实、待核、建议和表格都回到同一事项。领域助手只接收其所属模块有权查看的背景；需要跨部门汇总时，董事长可选经营决策助手。 |
| 11 | 在寻源助手的行动项上点「确认为处置」，填回执（保持勾选「模拟回执」），点「处置已完成，提交验证」 | 状态走到「待验证」。强调：回执只说明做过了。 |
| 12 | 点「按业务数据重新验证」 | 系统按当前库存重新计算，线束03 仍是缺料风险，**验证未通过**，事项回到第 2 轮处理中，第 1 轮记录原样保留。这就是「做过了」不等于「有效」。 |
| 13 | 再提交验证，用「人工核验：通过」，判据填「线束03 库存回到安全库存以上」，证据填「演示用模拟盘点单：假设在库 3000 件，非实际库存记录」 | 展示人工核验的状态流转，记录标注「非系统自动证实」并保存判据、证据来源、确认人。实际库存没有变化，不把此步骤当作已实现的改善效果。 |
| 14 | 填写适用条件保存经验卡；再从信号里对「AGV-02 配送连续超时」发起协作 | 新事项里出现「类似事项的已验证经验」，展开能看到适用条件、措施、来源事项和验证方式；引用后只作参考，不改变新事项的状态。 |
| 15（可选） | 点击页头「退出登录」，再用 `hr` 账号登录看「协作事项」 | 按上述流程新建的事项没有 HR 参与，HR 看不到它们，也不能通过链接打开；若已有其他 HR 事项，列表不一定为空。 |

收尾一句：平台对应达智汇 DARL 的四张网——指标（各模块对照制度的目标）、感知（事件与前兆规则）、决策（智能体与简报）、执行（行动项进待办）。

## 四、出问题时

- **想从头再来**：在跑服务的终端按 `Ctrl+C`，然后 `npm run seed`、`npm run dev`，刷新浏览器重新登录。
- **模型很慢或断网**：系统会自动改用规则分析作答（回答上标「规则分析」），数字和结论都来自确定性计算，演示流程不受影响。也可以把 `.env` 里的 `LLM_API_KEY` 清空后重启，全程用规则模式。
- **回放时报 401 或 503**：核对 `.env` 的 `BRIDGE_TOKEN` 非空且与服务一致，并确认 `AGENTOS_URL` 没有指向旧远程地址。改完配置后重启当前运行方式的服务。

## 五、常见问题

| 现象 | 处理 |
|---|---|
| `npm run dev` 报端口被占用 | macOS：`lsof -i :5173` 或 `lsof -i :8787` 找到进程后关掉；Windows：`netstat -ano \| findstr 5173` 后在任务管理器结束对应进程 |
| 登录提示密码错误 | 密码是 `.env` 的 `DEMO_PASSWORD`；改过 `.env` 要重启服务 |
| seed 之后页面数据没变 | 服务没停就 seed 了，运行中的服务还拿着旧数据：`Ctrl+C` 停服务，再 `npm run seed`、`npm run dev` |
| 回答都标「规则分析」 | 密钥留空时属于正常的离线模式；只有预期使用模型时，才检查密钥与网络并重启 |
| 页面空白或地址打不开 | 开发模式确认 server 和 web 两路日志正常，打开 5173；构建模式确认已执行 `npm run build`，启动 `npm start` 后打开 8787 |
| `node -v` 低于 22.13 | 升级 Node.js 后删掉 `node_modules` 重新 `npm install` |
