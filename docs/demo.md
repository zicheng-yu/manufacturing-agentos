# 演示手册：在自己电脑上跑起来并完成演示

这份手册给要在自己电脑上演示的队友。按顺序做完「一、准备」，演示当天按「二、开场前」和「三、演示流程」走即可。整个演示只用董事长账号。

## 一、准备（演示前一天做完）

### 1. 装好 Node.js 和 Git

- Node.js **22.13 或更高**：终端运行 `node -v` 确认。没有就到 nodejs.org 下载 LTS 版安装。
- Git：终端运行 `git --version` 确认。

### 2. 拿代码、装依赖

```bash
git clone https://github.com/zicheng-yu/manufacturing-agentos.git
cd manufacturing-agentos
npm install
```

`npm install` 很慢或失败时，先换国内镜像再装：

```bash
npm config set registry https://registry.npmmirror.com
```

### 3. 配置 `.env`

在项目根目录复制一份配置（已有 `.env` 时不要覆盖）：

- macOS / Linux：`cp -n .env.example .env`
- Windows PowerShell：`if (!(Test-Path .env)) { Copy-Item .env.example .env }`

用编辑器打开 `.env`，只需要改两处：

| 配置 | 填什么 |
|---|---|
| `LLM_API_KEY` | 模型密钥，向子程要。**只放在自己电脑的 `.env` 里，不要发群、不要提交到仓库** |
| `DEMO_PASSWORD` | 自己定一个演示登录密码，记住它 |

其余保持默认：模型是 MiniMax-M3.1-Flash，数据集默认是赛道官方素材包。

### 4. 第一次跑通

```bash
npm run seed
npm run dev
```

浏览器打开 http://localhost:5173 ，账号 `chairman`，密码是你在 `.env` 里设的 `DEMO_PASSWORD`。

检查三件事：

1. 驾驶舱顶部横幅、六张态势卡都正常显示，右上角显示「实时连接」和 `MODEL · MiniMax-M3.1-Flash`。
2. 进「智能体工作台 → 寻源比价助手」，点示例问题「线束快断货了，几家供应商怎么选？」，文字会边生成边出现，几秒后出现比价表、评分卡和行动项。
3. 能回答说明模型可用；如果答案标着「规则分析」，说明模型没连上（见「五、常见问题」），演示仍然可以进行。

确认无误后在终端按 `Ctrl+C` 停掉服务。

## 二、开场前（演示开始前 10 分钟）

1. 关掉其他可能占用 5173、8787 端口的程序（包括之前没关的本项目终端）。
2. 重置数据并启动（**先停服务再 seed**）：

   ```bash
   npm run seed
   npm run dev
   ```

3. 浏览器全屏，页面缩放 100%，用 `chairman` 登录，停在「经营驾驶舱」。
4. **另开一个终端窗口**，进入项目目录，输入好 `npm run replay` 但先不要回车。
5. 不要提前回放，也不要在生成简报前先去问各个智能体：回放产生的 AGV 信号只在 2 小时内有效，智能体的问答也会写入待办和事件。

## 三、演示流程（约 4 分钟）

| 步骤 | 操作 | 讲什么 |
|---|---|---|
| 1 | 停在驾驶舱 | 这是董事长视角。六张态势卡来自赛道官方素材包：线束03 约 3 天后断料、多张工单预计延期、8 单致命不良未开 8D、AGV 按时率 83.7%、30 起高风险违规未闭环。每张卡都能点进去看原始数据。 |
| 2 | 在第二个终端按回车运行 `npm run replay` | 现场事件实时上报：注塑机 EQ-IM-012 振动进入故障前兆区 → AGV-02 送线束03 连续超时 → 苏州精工科技交付能力下降 → 振动超限 → 供应链部离职预警。看态势卡依次变化（约 25 秒）。 |
| 3 | 在「活跃信号」里点「EQ-IM-012 振动超限」 | 信号可以回溯到原始事件。回看素材包 16 次故障，每次之前都出现过「24 小时内 3 次读数进入 2.8 mm/s 关注区」，从那一刻算平均约 28.8 小时后出故障；这台设备历史上约 18 小时后发生过定位精度超差。注意这是故障样本回看，不是预测准确率。 |
| 4 | 点横幅里的「生成今日决策简报」 | 三件需要董事长决定的事，每件有负责人、时限和依据信号。「跨部门关联」把供应链缺料、AGV 配送超时和生产 OEE 的「缺料待料」损失串在一起。 |
| 5 | 进「智能体工作台 → 经营决策助手」，问「只能先做一件事，做哪件？」 | 按排序依据（严重度、是否需董事长拍板、时间窗）给出先做哪件，其余由谁跟进。 |
| 6 | 「寻源比价助手」问「线束快断货了，几家供应商怎么选？」，再追问「这笔采购要走什么审批？」 | 按《供应链管理制度》5.2 给五家供应商打分，4.1 给出审批路径；断料只剩几天时，按 4.2 走紧急采购（供应链经理先批后补）。 |
| 7（可选） | 左侧「公司制度助手」问「年假有几天？」，按提示回答「我入职 3 年了」 | 制度问答只引用官方制度原文（6.4 假期管理），并核对数字。 |

收尾一句：平台对应达智汇 DARL 的四张网——指标（各模块对照制度的目标）、感知（事件与前兆规则）、决策（智能体与简报）、执行（行动项进待办）。

### 备用问题（都已实测）

| 智能体 | 问题 |
|---|---|
| 数据发现助手 | 平台数据还有哪些发现？ / 核验提前预警的计算口径 |
| 设备健康助手 | 哪些设备振动异常？ / EQ-IM-012 要不要马上停机检修？ |
| OEE 分析助手 | 最近一周哪条线 OEE 最差？ → 为什么？怎么改善？ |
| 排产助手 | 哪些工单会延期？ / 按什么策略排产延期最少？ |
| 库存补货助手 | 哪些物料快缺料了？ / 线束03 安全库存够不够？ / 哪些物料呆滞最久？ |
| 不良分析助手 | 哪些致命不良还没开 8D？ → 按制度应该怎么处理？ |
| AOI 复核助手 | AOI 漏检率是多少？要不要调阈值？ |
| 注塑工艺助手 | 注塑参数怎么设最好？ |
| AGV 调度助手 | 哪台 AGV 超时最多？ → 怎么改善？ |
| EHS 安全助手 | 有哪些高风险违规还没闭环？ |
| 能耗优化助手 | 怎么降低电费？ |

## 四、出问题时

- **想从头再来**：在跑服务的终端按 `Ctrl+C`，然后 `npm run seed`、`npm run dev`，刷新浏览器重新登录。
- **模型很慢或断网**：系统会自动改用规则分析作答（回答上标「规则分析」），数字和结论都来自确定性计算，演示流程不受影响。也可以把 `.env` 里的 `LLM_API_KEY` 清空后重启，全程用规则模式。
- **回放时报 401 或 503**：`.env` 里的 `BRIDGE_TOKEN` 不能为空，改完要重启 `npm run dev`。

## 五、常见问题

| 现象 | 处理 |
|---|---|
| `npm run dev` 报端口被占用 | macOS：`lsof -i :5173` 或 `lsof -i :8787` 找到进程后关掉；Windows：`netstat -ano \| findstr 5173` 后在任务管理器结束对应进程 |
| 登录提示密码错误 | 密码是 `.env` 的 `DEMO_PASSWORD`；改过 `.env` 要重启服务 |
| seed 之后页面数据没变 | 服务没停就 seed 了，运行中的服务还拿着旧数据：`Ctrl+C` 停服务，再 `npm run seed`、`npm run dev` |
| 回答都标「规则分析」 | `LLM_API_KEY` 没填或网络连不上 api.minimaxi.com；检查后重启 |
| 页面空白 | 确认两个服务都起来了（终端里有 server 和 web 两路日志），刷新页面 |
| `node -v` 低于 22.13 | 升级 Node.js 后删掉 `node_modules` 重新 `npm install` |
