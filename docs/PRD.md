# 达智汇 Manufacturing AgentOS — 产品需求文档（PRD）

> 面向「AI+智能制造」赛道（命题企业：达智汇科技服务（苏州）有限公司）
> 一个平台覆盖供应链、品质、HR、智能物流四个命题，以「身份解锁 + 共享工作记忆 + 事件上卷」为内核的制造业智能体操作系统。

## 0. 一句话定位

**AgentOS：为制造企业解决问题的智能体操作系统。** 每个岗位用自己的身份登录，解锁属于自己的智能体与数据；一线发生的每一件事沿「一线 → 分管经理 → 董事长」自动上卷，同一个事实在不同层级以不同粒度呈现。

## 1. 背景

### 1.1 赛道命题

| # | 命题 | 聚焦日常 | AI 价值 |
|---|---|---|---|
| 1 | 供应链 | 采购、寻源、比价、库存 | 提升信息处理与采购决策效率 |
| 2 | 品质 | 客诉、品质异常、改善分析 | 更快完成问题整理、信息检索与改善 |
| 3 | HR | 招聘、员工服务、培训 | 提升员工服务与信息处理效率 |
| 4 | 智能物流 | 汽车制造厂内混合料箱识别、抓取、搬运、码垛 | 基于统一仿真环境开发机器人控制程序，具备放置检查与异常处理 |

主办方说明四个命题仅作参考，鼓励拓展。原文见 [competition.md](competition.md)。

### 1.2 判断

四个命题在真实工厂里互相牵动：物流码垛异常会造成入库积压和缺料，缺料会追溯到来料品质，关键岗位减员会放大交付风险。如果做成四个独立的 AI 工具，评委看到的是拼盘；把它们放进同一个平台，并让事件在组织里自动流动，才是对"可拓展"最有力的回应。

## 2. 产品定位

### 2.1 三大支柱

| 支柱 | 含义 |
|---|---|
| 身份解锁的岗位智能体 | 用什么身份登录，就解锁什么智能体与数据。权限既是安全边界，也是为每个角色裁剪过的工作台。 |
| 共享工作记忆 | 一次录入，全域复用。记忆带来源、带类型（事实 / 待核 / 建议）、带责任人，有权限的智能体都能调用。 |
| 事件上卷 | 一线事件自动聚合为经理层信号、董事长层态势，可触发跨部门智能体协同。 |

### 2.2 与四命题的映射

| 命题 | 承载模块 |
|---|---|
| 供应链 | 供应链模块：寻源、比价、库存补货 |
| 品质 | 品质模块：客诉受理、8D 改善、品质案例检索 |
| HR | HR 模块：员工服务问答、招聘、组织健康 |
| 智能物流 | 仿真控制程序（独立子系统）+ 物流模块：现场看板、异常事件 |
| 拓展 | 经营驾驶舱 + 事件上卷 + 跨部门协同，贯穿全部命题 |

## 3. 角色与权限

| 角色 ID | 岗位 | 可用模块 |
|---|---|---|
| `executive` | 董事长 | 全部模块、全部事件、账号管理 |
| `supply_mgr` | 供应链经理 | 供应链 |
| `quality_mgr` | 品质经理 | 品质 |
| `hr_mgr` | HR 经理 | HR |
| `logistics_mgr` | 物流主管 | 智能物流 |

- 权限模型：角色 → 可见模块集合；智能体、事件、记忆、数据都按模块归属判断可见性。
- 事件字段裁剪：每类事件可声明对某些角色隐藏的字段（例如离职预警的员工姓名只对 HR 与董事长可见）。
- MVP 演示只用董事长账号，其余角色保留在系统里并有测试覆盖，用于说明权限隔离。

## 4. 系统架构

```
┌──────────────────────────────────────────────────────────────┐
│ 交互层   Web：经营驾驶舱 | 智能体工作台 | 模块页 | 事件中心        │
├──────────────────────────────────────────────────────────────┤
│ 智能体层  供应链 / 品质 / HR / 物流 / 经营决策 Agent               │
│          确定性分析（比价归一、案例检索、政策检索）+ 模型撰写结论      │
├──────────────────────────────────────────────────────────────┤
│ 事件层   Event（一线）→ Signal（经理）→ Situation（董事长）        │
│          去重合并、阈值规则、字段裁剪、SSE 实时推送                 │
├──────────────────────────────────────────────────────────────┤
│ 记忆层   共享工作记忆（事实 / 待核 / 建议）| 待办                  │
├──────────────────────────────────────────────────────────────┤
│ 接入层   智能体结论 | 仿真事件桥（HTTP）| 演示回放脚本               │
├──────────────────────────────────────────────────────────────┤
│ 模型层   OpenAI 兼容接口（通义千问等）；未配置时离线规则模式          │
└──────────────────────────────────────────────────────────────┘
```

**模块化**：每个领域是一个独立模块，自带数据表、演示数据、智能体、事件类型、信号规则、态势卡和模块页。新增功能只改自己模块的目录，通过 PR 合入，互不冲突。约定见 [architecture.md](architecture.md)。

技术栈：TypeScript 全栈；服务端 Node + Hono + SQLite（`node:sqlite`）；前端 React + Vite + Tailwind；测试 Vitest。

## 5. 核心创新：事件上卷

### 5.1 三层对象

| 对象 | 层级 | 产生方式 | 示例 |
|---|---|---|---|
| Event | 一线 | 智能体结论、仿真事件桥、演示回放 | 码垛-02 抓取失败 |
| Signal | 分管经理 | 同类 Event 在时间窗内累计达到阈值，可按工位、物料、部门分组 | 30 分钟内码垛-02 抓取失败 3 次 |
| Situation | 董事长 | 每个模块一张态势卡，由该模块的 Signal 与业务数据计算 | 厂内物流产能：告警 |

聚合与阈值用确定性规则，结论可解释、可回溯到原始事件；模型只负责撰写摘要与处置建议。

### 5.2 事件模型

```json
{
  "id": "EVT-…",
  "domain": "supply | quality | hr | logistics",
  "type": "grasp_failed",
  "severity": "info | warn | critical",
  "title": "码垛-02 抓取失败",
  "summary": "…",
  "payload": { "…领域字段…" },
  "source": { "channel": "agent | bridge | replay | seed", "station": "码垛-02", "actor": "…" },
  "dedupeKey": "logistics:grasp_failed:码垛-02",
  "count": 3,
  "status": "open | acknowledged | resolved",
  "createdAt": "ISO",
  "lastSeenAt": "ISO"
}
```

- **去重合并**：同一 `dedupeKey` 的未关闭事件在 10 分钟内重复出现时累加 `count`，不重复刷屏。
- **状态流转**：open → acknowledged → resolved，由有该模块权限的角色操作。
- **实时推送**：事件、信号、态势变化通过 SSE 推送到有权限的在线用户，目标延迟 < 5s。

### 5.3 跨部门协同

critical 级别的信号可触发多个智能体协同，结论汇到同一处。Demo 固化两条剧本，不做通用编排引擎：

1. 关键物料到货延迟 → 供应链 Agent 找替代货源 → 经营决策 Agent 给董事长出处置建议
2. 码垛异常致入库积压 → 品质 Agent 核查是否与来料品质有关 → 供应链 Agent 评估缺料风险

## 6. 功能模块

### 6.1 经营驾驶舱（董事长）

- 四张态势卡：供应链在途风险、品质、厂内物流产能、组织健康
- 活跃信号与实时事件流
- **今日决策简报**：经营决策 Agent 读取态势、信号、记忆，输出"今天最需要决定的 3 件事"，逐项写明影响、建议负责人、完成时间
- 待办：智能体结论中的行动项

### 6.2 智能体工作台

三栏：左侧智能体与对话，中间对话，右侧结果资料（表格、行动项、产生的事件）。每轮回复区分**事实 / 待核 / 建议**；同一智能体可开多条对话；删除一轮会连带删除它写入的记忆、待办与事件。

### 6.3 供应链模块（命题 1）

- 寻源与比价：多家报价按含税价、MOQ、交期、付款条件归一，输出比价表与推荐，未确认项标为待核
- 库存补货：库存 + 在途 + 日耗 → 可用天数、缺料预警、补货建议
- 事件：到货延迟、缺料风险、价格上涨、供应商风险

### 6.4 品质模块（命题 2）

- 客诉受理：结构化记录（客户、产品、批次、现象），自动检索历史同类案例
- 8D 改善：引导式整理问题描述、根因、对策，整改项进入待办，逾期升级为事件
- 事件：客诉、同类异常复发、8D 逾期

### 6.5 HR 模块（命题 3）

- 员工服务问答：基于政策库回答考勤、假期、社保、报销等高频问题，答不了的转人工并记录
- 招聘：关键岗位空缺、候选人进度
- 组织健康：编制与在岗、关键岗位空缺、离职预警（员工隐私字段按角色裁剪）
- 事件：离职预警、关键岗位空缺、服务请求积压

### 6.6 智能物流（命题 4）

- **仿真控制程序**（独立子系统）：在主办方统一仿真环境中完成混合料箱识别、精准抓取、分类搬运、按规则码垛，以及放置检查与异常处理
- **物流模块**（平台侧）：现场看板（识别、抓取、码垛成功率、节拍、积压）与异常事件
- **仿真事件桥**：仿真侧通过 HTTP 上报事件与指标，协议见 [event-bridge.md](event-bridge.md)；仿真不可用时用回放脚本兜底

## 7. 非功能需求

- **权限隔离**：服务端统一判断模块可见性，无权限的模块、智能体、事件不出现
- **可信**：每条结论区分事实 / 待核 / 建议；信号可回溯到原始事件；界面标注"演示数据"
- **可离线演示**：未配置模型时以规则模式运行，全流程在一台机器上闭环
- **可并行开发**：模块目录相互独立，核心接口有测试保护

## 8. Demo 主线：一颗螺丝的涟漪（董事长视角）

1. 董事长登录驾驶舱，四张态势卡大多正常
2. 回放开始：码垛-02 连续 3 次抓取失败 → 物流卡转为告警，信号出现在列表
3. 入库暂存区积压 → L1 线 FPC 柔性电路板缺料风险 → 供应链卡转为关注
4. FPC 供应商到货延迟 3 天 → 供应链卡转为告警
5. 客户投诉 FPC 金手指氧化 → 品质 Agent 检索到历史同类案例，品质卡出现"同类异常复发"
6. 供应链部 2 名采购工程师离职预警 → 组织健康卡提示供应链团队减员
7. 董事长生成今日决策简报：三件事、负责人、完成时间
8. 董事长进入供应链 Agent 问"FPC 有无替代货源"，得到归一后的比价表
9. 收尾：四个命题、一个平台、一条事件链串起全组织

## 10. 创新点

1. **全命题一体化**：一个平台 + 身份解锁覆盖四个命题
2. **事件上卷**：Event → Signal → Situation，命题间的关联在董事长面前一眼可见
3. **跨部门协同**：一个事件触发多个智能体，产出可执行建议
4. **可信 AI**：确定性分析 + 模型撰写；事实 / 待核 / 建议分离；可回溯
5. **可并行扩展**：模块化架构，新增能力即新增模块

---

## 11. 范围与风险

- **不做**：附件正文解析（赛题未要求）、联网检索（后续视需要再加）
- **仿真对接**：依赖主办方仿真环境接口；回放脚本作为兜底演示路径
- **数据真实性**：系统内业务数据均为演示数据，不代表达智汇实际经营情况
- **模型**：赛事是否指定模型待确认；模型层为 OpenAI 兼容接口，可切换
