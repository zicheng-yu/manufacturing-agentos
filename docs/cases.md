# 协作事项（YOU-143）

同一件业务事，多个岗位接力，证据持续更新，结果可以验证。事项是一个持久的业务对象：它保存引用和处理过程，业务表仍是事实来源，不复制一套库存或品质台账。

## 怎么用

1. 在驾驶舱点开一条信号，或在数据发现助手的卡片上点「发起协作」。同一个来源再点只会打开原事项。
2. 事项页分三块：关联证据、岗位行动、验证记录。
3. 由负责人（发起人）或董事长管理事项：确认处置、提交验证、验证、保存经验。任何能打开事项的岗位都可以请助手分析、提交回执、加入关联信号。

## 状态

`待处理 → 处理中 → 待验证 → 已验证`

- 确认第一项处置后进入「处理中」。
- 每项处置都有回执后，负责人才能提交验证，进入「待验证」。
- 验证通过进入「已验证」；未通过回到「处理中」并开始新一轮，之前的处置、回执和验证记录原样保留。
- 回执和已完成的待办只说明「做过了」，不会改变验证结果。
- 已验证之后，同一信号再出现新的记录，事项标为「需复核」，原验证记录不被覆盖；负责人可重新开启下一轮。

## 验证怎么做

- **系统重算**：事项涉及的物料，按当前库存、在途订单和日耗重新计算状态，恢复为「正常」才算通过。目前只有物料库存可以由系统重算。
- **人工核验**：必须写明判据和证据来源，记录里标注「非系统自动证实」，并保存确认人和时间。
- 官方素材包是静态数据，回执不会改变库存，所以演示里的系统重算会如实显示「未通过」。需要走到「已验证」时，用人工核验，并在回执里勾选「模拟回执」。

## 权限

- 事项对来源模块的岗位和已有内容参与的岗位可见，其他岗位看不到，也查不到它存在。
- 参与进来不会打开其他部门的数据：证据、事件字段（含 HR 隐私字段）、待办、关联线索、经验卡和给助手的背景摘要，都按当前账号的权限重新生成。
- 助手只能用该账号本来可用的助手。员工自助助手只服务个人，不参与事项。
- 业务写入仍走各模块自己的接口，模型的文字不会直接执行任何操作。

## 关联线索

其他部门的信号如果与事项有共同物料、供应商、设备等带类型的编号，或共同的原因标签，会作为线索列出，并写明关联依据。线索要人点「加入事项」才成为证据。共同实体和标签只说明值得联合核查，不代表已验证的因果。

## 经验卡

已验证的事项可以由负责人确认保存一张经验卡：对象和症状、适用条件、措施、验证结果、有效或无效、来源事项、确认人和时间。之后的相似事项（同一类信号，或有共同物料、设备等对象）会看到它，可以引用为参考。引用只是参考，不改变该事项的状态，也不能替代它自己的验证。

## 接口

| 接口 | 说明 |
|---|---|
| `GET /api/cases` | 当前账号可见的事项 |
| `POST /api/cases` | `{signalId}` 或 `{turnId, findingId}`，返回 `{id, created}` |
| `GET /api/cases/:id` | 事项详情，按账号裁剪 |
| `POST /api/cases/:id/{candidates,ask,actions,receipts,submit,verify,reopen,lesson,references}` | 各步骤，返回最新详情 |

## 边界

- 事项、处置和验证是平台内的记录，没有对接真实的 MES、WMS 或设备。
- 回执在演示里是人工录入，勾选「模拟回执」会在记录里标明。
- 经验卡只做手动确认保存和按信号类型、共同对象的简单匹配，没有向量检索或自动沉淀。
- 实现在 `apps/server/src/executive/cases.ts`，表是 `cases`、`case_entries`、`case_lessons`，测试在 `apps/server/test/cases.test.ts`。
