# 平台数据发现与量化口径（YOU-132）

董事长登录后进入「智能体工作台 → 数据发现助手」，问「平台数据还有哪些发现？」。所有结果每轮从平台已入库业务表重算，使用现有事实、表格与记忆展示，不依赖独立分析文件；该助手仅在官方数据集可见，仅董事长有权调用。

当前覆盖七项：预警实际触发时间、呆滞库存金额、零产量用电、AGV超时集中度、高置信度漏检、A级不良闭环缺口、排产方案比较。每项同时返回观察、分母、计算口径、来源表和可追溯记录。结果属于官方**仿真素材**中的观察或试算，不是实际生产效果。

## 复算

```bash
npx tsx scripts/evaluate-official-evidence.ts 2026-10-30 > findings.json
npm test
npm run typecheck
```

脚本在内存库中加载与平台相同的官方素材，调用同一计算函数；不读取 `.env`、不调用模型、不修改运行中的数据库。传入日期决定排产起算时间，因此对比方案时必须保持同一天。默认日期为演示基准 2026-10-30。供应链/物流/能耗等观察使用素材全期，预警按每次维修前72小时回看；日期窗口见各项依据和明细。

## 必须保留的解释边界

- 预警提前量从**第三条**满足24小时窗口的关注区读数开始计算，同一时间戳只计一次，故障发生时与之后的读数不计入。16条维修样本的覆盖率不能代替全时段的预测准确率；当前未计算误报率。原设备助手也使用这一口径，首次异常时间与规则触发时间分别列出。
- 库存占用按数量乘记录单价，≥90天是分析筛选条件，不是会计减值或报废标准；占用金额不等于可回收现金。
- 零产量用电可能来自保温、辅机或计量口径，核查前不能把金额称为可节省电费。
- AGV超时贡献按超时单数排序，并同时展示任务量；剔除起终点相同的异常记录。按时率与制度中的「任务自动执行率」是不同指标，不能互相替代。
- AOI漏检定义为AI判PASS、人工复核NG。置信度≥0.9仅用于分组；人工复核是素材标签，阈值同批回看不是独立测试验证。
- A级不良按不良单号计数；D7–D8只是原表阶段标签，不替代验证证据或客户确认。
- 排产试算沿用平台现有有限产能算法，未录入物料约束、人员班表与在制，不可表述为上线后延期已实际减少。
